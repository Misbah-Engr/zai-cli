# Native full access: retained in 0.2.0

## Commands

In the ZC native prompt box, use `/mode yolo`. Select Enable YOLO and press Enter.
The current native session is changed in place, without replacing the frontend,
logging in again, clearing the conversation, or submitting a task. Use `/mode ask`
to return to the previous guarded policy. Stop an active turn with Escape first.
Use `/mode` to inspect the last acknowledged mode.

The footer is text-labeled YOLO / FULL ACCESS and uses the warning palette. It
remains explicit in monochrome. Light-theme footer controls and code now use darker
colors; existing user theme preferences are preserved.

## Contract

The adapter sends `session/setMode` with the current sessionId and `mode: yolo`
or `mode: guarded`. It verifies the session identity and the runtime's reported
mode from the snapshot. Live settings.permission.mode / settings.mode.current take
precedence over session.mode, which can be a lagging reducer projection. An ack without a snapshot is followed by `session/read`.
No model prompt is generated by either command. If mode mutation fails ambiguously,
new prompts and compaction are blocked until explicit guarded reconciliation.

This feature does not remove a read-only session's tool allowlist. Open a new native
connection using `--mode ask` first. It is not implemented for native-stream or the
direct API backend. Global configuration continues to reject `mode: yolo`, so
changing a theme or switching workspaces cannot accidentally persist full access.
New/resumed native connections reapply their launch policy before new user input.

Native runtime safeguards are not replaced. Requests still requiring user permission
are shown, not blindly approved. The runtime's independent plan state may restrict
execution even while the permission mode is YOLO. A full-access label is a permission
mode, not a claim that a task succeeded or that every future request is unattended.

- https://github.com/kingsword09/zcode-cli/blob/v3.15.3-37/docs/CONFIGURATION.md

The upstream permission service checks user-interaction and alwaysAsk conditions
before its YOLO shortcut. ZC preserves that boundary rather than synthesizing an
allow response to all reverse requests. Shared account authentication belongs to
the installed client, not this feature. No upstream runtime file is patched.

## Validation boundary

See [VALIDATION.md](VALIDATION.md) for actual local results. Subprocess fixtures exercise the real
ZC protocol client and renderer, but they are not the official runtime. There was
no authenticated ZCode installation available in this build environment. Live
full-access switching and unattended edits on the user's VPS remain unverified.
